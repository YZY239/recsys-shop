# 免费部署指南（无需买服务器）

> 前提：项目已经是 Docker 化的，两条路线都不需要额外改代码。
> `render/` 目录是为"单容器托管"准备的（nginx 托管前端 + 反代同容器 gunicorn），与本地 `docker-compose.yml` 互不影响。

---

## 路线 A：cpolar 内网穿透 —— 5 分钟拿到公网链接（适合课堂演示）

原理：项目在**你自己电脑**上跑，cpolar 把本机 8080 端口映射成一个公网 HTTPS 地址。

1. 本地启动项目（二选一）：
   - 有 Docker：项目根目录 `docker compose up -d`，访问 http://localhost:8080
   - 无 Docker：双击 `start.bat`（分别起后端 5000 和前端 5173）
2. 到 [cpolar 官网](https://www.cpolar.com) 注册（免费），下载 Windows 客户端并解压
3. 在官网后台复制 `authtoken`，执行一次配置：
   ```
   cpolar.exe authtoken 你的token
   ```
4. 开隧道（端口对应第 1 步的服务）：
   ```
   cpolar http 8080        # Docker 版
   cpolar http 5173        # start.bat 版
   ```
5. 终端会输出一个 `https://xxxx.r21.cpolar.top` 公网地址，**用 HTTPS 打开**分享给别人即可。

**限制与注意**：
- 免费版域名**每次重启会变**，演示前重新生成一下即可
- 免费隧道带宽约 1Mbps，纯页面演示足够，别放视频
- 国内运营商封免费隧道 80 端口，**务必用 https:// 链接访问**（443 正常）
- 你的电脑关机 = 网站下线；正式提交前建议当场演示

## 路线 B：Render 免费托管 —— 24 小时在线（适合把链接写进作业）

原理：把整个项目打成**一个 Docker 镜像**推到 Render，它给你一个 `https://xxx.onrender.com` 的固定域名，不用自己开机。

免费档现状（2026-09 核实）：512MB 内存、0.1 vCPU（本项目绰绰有余）、**15 分钟无访问自动休眠**、再次访问冷启动约 30~50 秒、免信用卡。

### 步骤

1. 把 `recsys-shop` 推到一个 **GitHub 公开仓库**（含 `render/` 目录）
2. 注册 [render.com](https://render.com)（可用 GitHub 账号直接登录）
3. 控制台 **New → Web Service** → 连接该仓库，然后按下面填：
   | 配置项 | 值 |
   |---|---|
   | Name | 随意（决定你的域名，如 `recsys-shop` → `recsys-shop.onrender.com`） |
   | Region | Singapore（离中国最近） |
   | Runtime | Docker |
   | **Docker Context** | `./`（仓库根目录） |
   | **Dockerfile Path** | `./render/Dockerfile` |
   | Instance Type | **Free** |
4. 点 **Create Web Service**，等首次构建（约 5~8 分钟，npm install + pip install）
5. 构建完成访问 `https://你的名字.onrender.com` → 登录 alice / 123456

### 免费档须知

- **数据不持久**：Render 免费档没有磁盘，休眠唤醒或重新部署会还原成镜像里的初始数据（注册的用户、收藏、购物车记录会丢）。演示场景可接受；作业里注明"演示数据为内置种子数据"即可
- **防休眠**：15 分钟无访问会睡，冷启动等 30~50 秒。可去 [UptimeRobot](https://uptimerobot.com)（免费）每 10 分钟 ping 一次你的域名保活
- 首次构建要拉 node/python 镜像 + 装依赖，慢是正常的，看 Deploy 日志排错

## 分享给其他人

### ① 分享网址（别人只需访问，不部署）

部署完成后直接把 `https://你的服务名.onrender.com` 发出去，**任何人打开链接就能用**，不需要注册 Render、不需要任何权限：

- 对方第一次打开如果碰上休眠，等 30~50 秒加载出来即可（配了 UptimeRobot 保活则基本秒开）
- 别人可以自己注册账号（注册页带兴趣标签冷启动），也可以用演示账号 alice / 123456
- 提醒对方：免费档重新部署后数据会重置，注册的账号可能丢失，重要演示前先确认能登录
- Render 免费档没有访问控制，链接谁拿到谁能看——不要把含敏感信息的演示数据放上去

### ② 分享部署方案（别人自己也能搭一套）

1. 把 `recsys-shop` 推到 GitHub **公开仓库**
2. 在 README 里加"一键部署"按钮（把 `<你的用户名>` 换掉）：
   ```markdown
   [![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/<你的用户名>/recsys-shop)
   ```
3. 其他人 fork 你的仓库后点这个按钮，Render 会读取仓库根目录的 `render.yaml` 自动按配置创建服务，**全程不用填任何参数**，两三分钟后就有自己的网址
4. 不走按钮也行：手动方式见上文路线 B；本地跑则克隆仓库后 `docker compose up -d` 或双击 `start.bat`

## 对比总结

| | 路线 A（cpolar） | 路线 B（Render） |
|---|---|---|
| 费用 | 0 | 0 |
| 上线耗时 | 5 分钟 | 半小时（含构建） |
| 在线时间 | 电脑开机才在线 | 24 小时（会休眠） |
| 域名 | 每次重启变化 | 固定 |
| 数据 | 本机 SQLite，持久 | 重部署会重置 |
| 适合 | 课堂/答辩现场演示 | 作业里写长期链接 |

**建议**：两条都用——作业文档里写 Render 的固定链接，答辩演示时备用 cpolar（万一 Render 冷启动慢，现场切本地 + 隧道最稳）。
